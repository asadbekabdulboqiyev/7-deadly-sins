# Next steps — concrete runbook

Everything below is ordered by value per hour. Each item lists the exact
commands, the file to touch and the definition of done. Nothing here is
speculative: the gaps were verified in the 2026-11-05 session.

---

## 1. Prove the ownership gate on a real domain (2 h)

**Why now:** the gate is the legal core of the product. It has only ever run
against lab targets (`verify_method: lab`) and mocks.

```bash
# You need a domain whose DNS you control.
export SINS_API_KEY=sins_...
uv run sins serve --port 8000 &
uv run python - <<'PY'
# simpler path: use the CLI helper
PY
uv run sins create-tenant --name "Ownership proof"
```

1. `POST /targets` with `{"value": "yourdomain.com"}`.
2. Read `instructions.dns_record` / `dns_value` from the response and publish
   the TXT record (`_sins-verify.yourdomain.com`).
3. `POST /targets/{id}/verify` → expect `verified_at != null`,
   `verify_method: "dns"`.
4. Negative test: delete the TXT record, wait for `verify_expires_at`, verify
   again → must fail with a clear message.

**Done when:** one positive and one negative verification are recorded in
`docs/RUNBOOK.md` with the real timestamps.

## 2. Expose KEV/EPSS on the findings API (half a day)

Today enrichment happens only inside report generation. The site cannot show
real intel until the API returns it.

- Add `kev: bool | None` and `epss: float | None` to `FindingOut` in
  `src/sins/api/schemas.py` (default `None` = not consulted).
- Reuse `sins.intel.enrich` inside `scan_service.list_findings`, or better:
  persist the intel on the `Finding` row at scan time (`evidence` JSONB

- Keep `SINS_THREAT_INTEL_ENABLED` as the single switch.

**Done when:** `GET /scans/{id}/findings` returns `kev: true` for a Log4j
finding and the field is documented in `docs/API.md`.

## 3. Bake the scanner binaries into the image (half a day)

The Docker image deliberately excludes `nuclei`, `osv-scanner`, `subfinder`,
`naabu` and `httpx`, so a container scan can only run `pride`/`envy`.

```dockerfile
# after the existing apt-get block in the runtime stage
ARG NUCLEI_VERSION=3.3.5
RUN curl -fsSL "https://github.com/projectdiscovery/nuclei/releases/download/v${NUCLEI_VERSION}/nuclei_${NUCLEI_VERSION}_linux_amd64.zip" \
      -o /tmp/nuclei.zip && apt-get update && apt-get install -y --no-install-recommends unzip \
    && unzip /tmp/nuclei.zip -d /usr/local/bin && rm /tmp/nuclei.zip
```

Repeat for `subfinder`, `naabu`, `httpx` (same release channel) and
`osv-scanner` (GoReleaser binary).

**Done when:** `docker compose exec api sins adapters` shows `ready` for all
seven engines and a container scan produces at least one finding on
`http://testphp.vulnweb.com` (or your lab target).

## 4. Real drift data on the site (1 day)

The site's Drift section is honest but static ("Illustrative timeline").

Two options, pick one:

- **Cheap:** add `GET /public/demo/drift` returning a frozen, seeded timeline
  generated by the real drift service, and fetch it client-side.
- **Proper:** run two scans of a lab target on a cron, store the diff, expose a
  read-only endpoint. Then delete the "illustrative" caption and the
  hard-coded payload in `sins-site/src/lib/content.ts`.

**Done when:** `sins-site/src/components/Drift.tsx` renders data fetched from
the API and the caption matches reality.
